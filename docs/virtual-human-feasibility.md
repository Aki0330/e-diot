# 虚拟人可行性调研（MVP 版）

> 日期：2026-11-19　作者：绫波 無夢　状态：调研结论，待评审
> 关联：E-diot 智账 · 记账 Agent / 人格 / 记忆 / 主动关怀

## 0. 一句话结论

**先做「2D 形象 + 中文语音 + 口型」的陪伴态 MVP（2–4 周、零 GPU 成本），现在不做实时 3D 和生成式视频数字人。**
虚拟人解决的是「愿意听」，前提是「说得对」——知识库和洞察没做扎实之前，形象越像真人，越容易放大不信任。

## 1. 我们要的虚拟人是什么

不是主播、不是客服、也不是「换皮聊天」，而是记账 App 里的一个**人格化存在**：

- 有固定形象与声音，和 `persona`（潜水 / i 人 / 搭子 / 话痨）一致；
- 有三种基本状态：**倾听、思考、说话**；
- 说话时嘴型跟着语音动，不追求影视级；
- 始终**可一键关闭**，关闭后不再请求麦克风/摄像头/语音；
- 不假装真人：界面明确标注「AI 助手」。

一句话：**它是记账工具的「脸」，不是另一个产品。**

## 2. 三条路线对比

| 维度 | 2D 形象 + TTS + 口型（推荐） | 预渲染视频（HeyGen / D-ID） | 实时 3D 数字人（UE / Unity + 云渲染） |
| --- | --- | --- | --- |
| 视觉上限 | 中（Live2D / VRM 风格化） | 高（真人级） | 高（可定制场景） |
| 实时互动 | ✅ 可实时对话 | ❌ 只能播预制视频 | ✅ 可实时 |
| 成本 | 低（现有电脑即可） | 中（按分钟计费） | 高（建模 + GPU 云渲染） |
| 看到效果 | 2–4 周 | 1–2 周 | 2–3 个月 |
| 技术栈 | Web + Live2D/VRM + TTS | 调 API + 视频播放 | Unity/UE + 推流 |
| 主要风险 | 表情动作有限 | 不能互动、口型对不上 | 延迟、算力、长期维护 |
| 适合场景 | **日常陪伴、记账对话** | 开场介绍、宣传片 | 发布会、大屏展示 |

结论：**MVP 选第一列**。第二列只在需要「宣传片」时用一次，第三列等有明确预算和场景再说。

## 3. 推荐架构

```
用户输入
  ↓
现有 /api/v1/chat（意图 + 记忆 + 人格 + 预算）
  ↓ 文本回复
TTS（Azure / 火山 / Edge TTS）
  ↓ 音频 + viseme 时间轴
口型驱动（viseme → VRM 表情 aa/ih/ou/ee/oh）
  ↓
Web 渲染（three.js + @pixiv/three-vrm 或 Live2D）
  ↑
状态机：idle → listening → thinking → talking → idle
```

### 3.1 形象层选型

| 方案 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- |
| **VRM + three-vrm** | 开源、模型多、Web 原生、可换装 | 3D 渲染略吃性能 | **首选**，先用官方示例模型 |
| Live2D + pixi-live2d-display | 2D 表情细腻、资源多 | Cubism SDK 授权、模型版权 | 有现成模型时再用 |
| Rive / Lottie 状态动画 | 最轻、最便宜 | 动作少、容易「假」 | 降级方案 |

> 不建议一上来做定制建模：先用现成 VRM 示例模型把「状态 + 口型 + 对话」跑通，再决定是否投入美术。

### 3.2 语音层选型

| 方案 | 成本 | 中文效果 | 风险 |
| --- | --- | --- | --- |
| Azure Speech | 免费额度 50 万字符/月 | 好，支持 viseme | 需注册、要网络 |
| 火山引擎 / 阿里云 | 按量，约几元/万字符 | 很自然 | 商务开通 |
| Edge TTS（非官方） | 免费 | 好 | 稳定性无 SLA，仅原型 |
| Piper（本地） | 免费、离线 | 一般 | 音色少 |

建议：**原型用 Edge TTS 快速验证，上线换 Azure 或火山**；TTS 失败时降级为纯文字，不阻塞对话。

### 3.3 口型方案

1. **viseme 时间轴（推荐）**：Azure TTS 会返回 viseme 事件，直接映射到 VRM 的五个口型参数，最准；
2. **能量包络**：按音频音量驱动开合，实现 1 天，够用但不同步；
3. **wav2lip / SadTalker**：视频级，重、慢、不适合实时，**不做**。

## 4. MVP 范围与里程碑

**范围**：一个形象 + 三种状态 + 中文语音 + 口型同步 + 一键关闭；不做定制形象、不做情感识别、不做实时视频。

| 周 | 交付 | 验收 |
| --- | --- | --- |
| 第 1 周 | VRM 渲染 + 状态机 + TTS 播放 + 能量包络口型；接 `/chat` 文本 | 说一句话能听到回复，嘴会动 |
| 第 2 周 | viseme 口型、人格/记忆联动、关闭开关、移动端适配、降级 | 首次出声 < 1.5s；关闭后零请求；手机 30fps 可用 |
| 可选第 3–4 周 | 形象微调、主动消息语音播报（需授权）、A/B | 关闭率、使用时长、有帮助率 |

**验收指标**：

- 首次出声延迟 < 1.5 秒（文字先到、语音后到也算达标）；
- 口型与语音偏差 < 150ms；
- 关闭虚拟人后不再发起 TTS/渲染请求；
- 移动端帧率 ≥ 30fps，低端机自动降级为静态立绘 + 语音；
- 用户可一句话说清「这是 AI」，不产生真人误解。

## 5. 成本估算

| 项 | MVP | 上线后 |
| --- | --- | --- |
| 开发 | 1 前端 + 0.5 后端 × 2 周 | — |
| 形象 | 现成 VRM：0 元 | 定制 500–3000 元 |
| 语音 | 免费额度内 0 元 | 约 0.5–1 元/万字符 |
| 服务器 | 无 GPU，复用现有 API | 无额外 |
| 对比：实时 3D | — | 云渲染约 2000+ 元/月 |
| 对比：视频数字人 | — | 约 1–5 元/分钟 |

## 6. 风险与边界

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 恐怖谷 / 过度拟人 | 越像真人，越难接受「它是 AI」 | 风格化 2D/VRM，明确标注 AI |
| 延迟 | TTS + 渲染叠加 | 文字先出、语音流式；低端机降级 |
| 隐私 | 声音/形象/对话敏感 | 默认关闭，开启需授权；不上传形象 |
| 情感依赖 | 陪伴类产品的伦理风险 | 定位为工具，不鼓励替代人际；可随时关闭 |
| 内容安全 | 理财/心理建议越界 | 沿用现有边界：不诊断、不荐股、不荐贷 |
| 技术不稳 | 第三方 TTS 故障 | 失败自动降级纯文字 |

## 7. 与现有系统的接入点

- `/api/v1/chat` 已返回 `response` 与 `graph_path`，前端只需在消息到达后触发 TTS 与口型；
- `user_settings.persona` 已存在，直接决定语气与动作幅度；
- `memories` 提供个性化称呼与话题边界，虚拟人只「演」，不新增记忆逻辑；
- 主动消息已有站内消息，可扩展为语音播报（必须用户授权）；
- 前端是 React 19 + Vite，接入 three-vrm 不需要改后端。

## 8. 不建议现在做的

- **实时 3D + 云渲染**：成本、延迟、维护都超出当前阶段；
- **生成式视频数字人**：不能实时互动，只适合开场或宣传片；
- **真人形象 / 声音克隆**：合规、信任与伦理风险高，且与「工具」定位冲突；
- **情感识别**：没有可靠数据前，容易变成「假装懂你」。

## 9. 本周可验证的 5 件事

1. 选 1 个 VRM 示例模型，在 Web 里跑通渲染与三种状态；
2. 用 Edge TTS 生成 3 条中文语音，记录首包延迟；
3. 做能量包络口型 demo，录 30 秒「说一句话 → 嘴动」；
4. 用现有 `/chat` 回复驱动，验证端到端；
5. 把 demo 给 3 个同学看，问两个问题：像不像 AI？愿不愿意开？
