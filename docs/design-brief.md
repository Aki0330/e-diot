# E-diot 汇报 HTML · 设计交接说明

> 用途：把这份说明直接交给 GPT / 设计类 AI，让它重做或迭代视觉。
> 当前文件：`apps/web/public/showcase.html`（在线：http://127.0.0.1:8000/showcase.html）
> 离线单文件：`docs/e-diot-showcase.html`（图片已内嵌，约 1.1 MB）

## 1. 这份 HTML 要做什么

- 8 页，给评委/老师现场看，也可以在电脑上直接双击离线打开。
- 固定 **1920×1080（16:9）** 画布，整体等比缩放；不按屏幕重排，不允许某页变高。
- 单文件，零外部依赖，图片 base64 内嵌。
- 中文口语，5 分钟内让评委记住三件事：解决什么问题、现在做到什么程度、凭什么。

## 2. 页面结构（当前 8 页）

| # | 页面 | 内容 |
| --- | --- | --- |
| 1 | 封面 | 「记一笔账，一句话就够了」+ 现场体验地址 + 6 个页面 / 188 个测试 |
| 2 | 问题 | 三个真实场景：22:41 想记账、月底只记得总数、账单日的账单和心痛 |
| 3 | 怎么做 | 「你说一遍，它帮你记清楚」四步；示例午饭 38 + 咖啡 19 + 打车 26 → 餐饮 57 / 交通 26 |
| 4 | 现在能用 | 3 张真实手机截图（对话记账、总览、账单） |
| 5 | 和谁比 | 5 行对比表：传统记账 App / 通用 AI / 银行账单 / E-diot |
| 6 | 怎么不乱记 | 3 条信任机制：规则校验、可改可删、记忆可查可删 |
| 7 | 接下来 90 天 | 3 件事 + 每件的完成标准 |
| 8 | 结尾 | 一句话总结 + 现场体验 / 代码仓库（团队信息待补） |

**明确不做**：不出现虚拟人/数字人；不向评委提问「该不该做虚拟人」。

## 3. 用户对设计的要求（原话归纳）

- 「太丑了」「全是纯色背景，没有设计感」。
- 「颜色大幅度跳变，对接收者刺激较大」——深色和米白不要硬切。
- 「深色可以稍微放浅」。
- 「每一页都一样大小」。
- 「说人话，看得懂」。
- 不要 AI 味：不要满页技术黑话、不要排比三连、不要「不是 X 而是 Y」的假对比。

## 4. 用户已经明确否定的东西

- 绿色色块压在「一句话」下面，把字挡住了（已改成青柠色字 + 细下划线）。
- 一页高、一页矮；内容溢出；字号忽大忽小。
- MOAT、P4b、BGE-M3、Reranker、D30、闭环、赋能、壁垒这类词。
- 在 HTML 里讨论虚拟人，或把产品决策抛给评委。
- 纯色平涂背景、深黑与米白硬切、满屏卡片。

## 5. 我尝试过的版本（避免重复踩坑）

| 版本 | 做法 | 结果 |
| --- | --- | --- |
| v1 | 9 页卡片 + 滚动全屏 | 内容多、技术词多、页面高度不一致 |
| v2 | 10 页 100dvh 滚动翻页，重写文案 | 有大段空白，页面仍不稳定 |
| v3 | 固定 1920×1080 舞台，8 页，加手机截图 | 平涂感强，绿块挡字 |
| v4 | 加 Pexels 实拍图（封面/问题页），绿块改下划线 | 明暗跳变太大，用户仍不满意 |
| v5 | 深色放浅为墨绿灰 `#232823`；中间演示页改浅色；背景加渐变 + 噪点；结尾用宋体 | 明暗跳变减小 |
| v6 | 在 v5 基础上加「大号描边页码」背衬、封面照片压暗、演示页柔光 | 用户认为仍是「组件拼装」 |
| v7（当前） | 放弃深色封面与卡片：纸面 + 全出血摄影；字号统一到 20px 以上；封面/问题/计划/结尾四页由照片承担视觉；保留固定舞台与真实截图 | 待确认 |

## 6. 当前实现要点（给设计 AI 的技术边界）

- 舞台：`#stage` 固定 1920×1080，`transform: translate(-50%,-50%) scale(min(vw/1920, vh/1080))`。
- 翻页：方向键/空格/点击左右半区；`location.hash` 支持 `#1`–`#8`。
- 字体：`Noto Sans SC`（中文正文）、`Bahnschrift`（数字/英文）、结尾标题用 `SimSun`。
- 字号（1920 画布）：封面 88、页面标题 72、正文 32、次要正文 24–28、注释/页脚 20–22；不再使用 20px 以下文字。
- 色板：纸 `#F4F0E6`、墨 `#1E2223`、青柠 `#C9F26B`、深绿 `#2A302A`、砖红 `#B6503A`。
- 背景：纸面 + 极淡噪点 + 顶部柔光；不再全篇平涂，也不再中途切换深色页。
- 图片：3 张手机截图（780×1688）+ 4 张 Pexels 编辑类摄影：
  - 封面：咖啡馆手机支付 `p-6612717.jpg`
  - 问题：收银台小票 `p-5239870.jpg`
  - 计划：摊开的日程本 `p-28353121.jpg`
  - 结尾：夜晚咖啡馆 `p-29446768.jpg`
- 动画：仅淡入 + 轻微上移，`prefers-reduced-motion` 时关闭。

## 7. 可以尝试的设计方向

1. **统一纸面 + 只在首尾用深色**：中间 6 页统一米白纸感，别在中间切黑；深色用墨绿灰而不是黑。
2. **照片满版 + 纸卡**：封面/演示页用满版实拍图，文字放在半透明纸卡上，减少平涂。
3. **账本/毫米纸纹理**：极淡的横线或网格做底纹，但不要每页都满格。
4. **衬线标题 + 无衬线正文**：中文标题可试宋体，正文保持黑体；数字用窄体。
5. **色彩收敛**：米白、墨、青柠、少量砖红；避免大面积纯黑或纯白。
6. **动效克制**：只做淡入/位移，不做花哨转场。

## 8. 可以直接发给设计 AI 的 Prompt

> 你是资深视觉设计师。请重做一份 8 页中文产品汇报 HTML，主题是「一句话记账」的记账 App。
> 硬性要求：
> 1. 固定 1920×1080 画布，整体等比缩放，8 页必须同尺寸，不能重排；
> 2. 单文件 HTML，CSS/JS 内联，图片可用我提供的截图与 Pexels 图片；
> 3. 页与页之间不要大幅明暗跳变，深色用墨绿灰（约 #232823），不要纯黑；
> 4. 背景不要纯色平涂，用极淡纹理/渐变/照片，但要克制；
> 5. 文案口语化，不用「闭环/赋能/壁垒/MOAT」这类词；不出现虚拟人；
> 6. 评委 5 分钟内能看懂：问题、现状、差异、下一步。
> 风格关键词：编辑部、账本、纸感、克制、青柠色点缀、少量砖红。
> 页面结构：封面 / 问题（3 个真实场景）/ 四步流程 / 3 张真机截图 / 对比表 / 3 条信任机制 / 90 天计划 / 结尾。
> 请先给 2–3 个封面方向，再统一成全套。

## 9. 验收标准

- 8 页同一画布，无溢出、无重叠、无文字被遮挡。
- 任意两页并排看，像同一套设计系统，而不是两套模板。
- 相邻页的明暗差不过分（主观上不刺眼）。
- 评委看完能复述：解决什么、做到什么程度、下一步做什么。
- 离线双击可开，图片不缺。
