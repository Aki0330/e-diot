01 / 我们解决什么问题

记账 App 最大的问题，
不是功能少，是记不下去。

我们问过自己和身边的同学：下载过记账 App 的人不少，能坚持一个月的很少。原因通常不是「不会记」，而是下面三件事。

01 · 太麻烦

一笔账要 8 步

打开 App、点加号、选支出、输金额、选分类、挑日期、写备注、保存；忙起来就懒得记。

02 · 记了没用

只是一串数字

知道自己花了多少，但不知道钱花在哪、哪笔花得不值、下个月该怎么调。

03 · 提醒很烦

要么不提醒，要么指责

平时一声不吭，一开口就是「你又超支了」；用户的第一反应是关掉通知。

所以我们把目标定得很具体：把「记一笔」从 8 步变成 1 句话，再让这笔记录至少产生一次有用的反馈。

06 / 为什么是我们

三件小事，
决定了体验差别。

01 · 听得懂，但不乱记

模型负责理解，规则负责对错

金额、分类、时间会按规则再校验一遍；听不懂就明确说，不会把「大概 50」记成 500。

02 · 预算当场算

记完就知道还剩多少

只有跨过 50% / 80% / 100% 才提醒；不制造焦虑，也不用天天看数字。

03 · 记忆可查可删

像对待自己的笔记本

每条记忆都能看到依据、能改、能删；删除后不再参与任何回复。

技术上是 TypeScript 全栈 + PostgreSQL，模型接口可替换；这些是细节，不影响上面的三条承诺。

不做的：医疗 / 心理诊断、具体理财推荐、无依据的结论、换皮陪聊。

07 / 接下来 90 天

只做三件事，
顺序不能反。

0–2 周 · 洞察 v1

把数字变成 3 条结论

这个月钱花在哪、哪类在涨、哪几笔偏离平常；每条都能点回原始账单。

验收：每条结论可核对，不出现「凭感觉」的观察。
2–6 周 · 知识库

回答「怎么省」时有出处

把理财常识与消费方法做成可检索的知识库，回答附来源和时间。

验收：Top-5 命中率、引用准确率、无出处回答占比。
6–12 周 · 虚拟人 MVP

先做「看得见的陪伴」

2D 形象 + 中文语音 + 口型同步，三种状态：倾听 / 思考 / 说话。

验收：人格一致、可一键关闭、不干扰记账主流程。
先让记录可信，再让陪伴有趣；洞察没做扎实之前，不上虚拟人。

08 / 虚拟人：可行性

先做「看得见的陪伴」，
不急着做「像真人」。

我们对比了三条常见路线。结论：用 2D 形象 + 语音 + 口型做 MVP，成本最低、两周能看到东西， 也最符合「记账工具里的陪伴」而不是「数字人主播」。

路线 成本 看到效果 主要风险 适合
2D 形象 + TTS + 口型 低（现有电脑即可） 2–4 周 表情动作有限 日常陪伴 · 推荐
预渲染视频（HeyGen / D-ID） 中（按分钟计费） 1–2 周 不能实时互动 开场介绍 / 宣传片
实时 3D 数字人 高（建模 + 云渲染） 2–3 个月 延迟、算力、维护 发布会 / 大屏
MVP 范围：一个形象 + 三种状态 + 中文语音 + 口型同步 + 一键关闭；先不做定制形象、情感识别和实时视频。

详细对比、开源选型与实施清单见 docs/virtual-human-feasibility.md。
