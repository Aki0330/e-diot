## 二、执行清单

### P0 · 必须先成立（约 6–9 人日）

- [x] **P0-1 对话历史注入**（已完成 2026-11-12）
  - Agent 读取同会话最近消息（默认 8 条 / 1800 字符预算，API 侧取 12 条），拼入意图解析与回复 prompt。
  - 验收：`selectHistory` 截断单测 + `parseIntent` 历史注入单测；对话路由已接入 `listMessages`。

- [x] **P0-2 人格与相处设置**（已完成 2026-11-12）
  - 新表 `user_settings` + 迁移 `0002`；API `GET/PUT /users/settings`。
  - 前端「我的」页新增「相处方式」：4 档人格、主动程度、关怀时间、免打扰、暂停。
  - Agent：4 套 persona 提示词（`withPersona`），只影响语气/长度。
  - 验收：接口默认值/持久化/非法时间用例 + persona 单测；真实库实测通过。

- [x] **P0-3 记忆系统 v1**（已完成 2026-11-12）
  - `memories` 表（迁移 `0003`）：type/content/source/source_ref/status/confidence/时间戳 + 软删除。
  - API：`GET/POST /memories`、`POST /:id/confirm`、`PATCH/DELETE /:id`、`GET /:id/basis`（交易/对话/手动依据）。
  - Agent：active 记忆按 `边界 > 目标 > 偏好 > 习惯` 取前 8 条，1200 字符预算注入回复 prompt。
  - 前端：新增「记忆」Tab（待确认 / 已生效 / 查看依据 / 纠正 / 删除）。
  - 验收：接口 CRUD + 注入单测通过；真实库写入 5 条记忆后用真实 LLM 验证，回复引用了「少糖奶茶 / 手冲咖啡」。
  - 存储决策：**v1 用 PostgreSQL，不先上 Milvus**，见 [memory-storage-decision.md](memory-storage-decision.md)。

- [x] **P0-4 主动关怀 v1（站内）**（已完成 2026-11-12）
  - 进程内调度器（60s tick）：`care_time` 后 2 小时内补发；固定 `Asia/Shanghai`；免打扰跨午夜判断，`care_time` 落在免打扰内直接跳过。
  - 规则按 `budget_over > budget_near > inactivity(≥3 天)` 取一条；无命中不发。
  - 频控：low 1/周、medium 1/天、high 2/天；`proactive_events` 唯一约束保证重启/重复 tick 幂等。
  - 文案：模板 + 4 种人格前缀（不调用 LLM）；消息写入 `chat_messages.is_proactive=true`。
  - 前端：消息「主动消息」标记、帮助/不准确/暂时别提醒反馈（mute = 暂停 1 天）；新增「历史会话」抽屉。
  - 验收：`runProactiveTick` 单测 + 临时库集成测试；真实库触发 inactivity 消息并用 API 反馈验证通过。

### P1 · 支撑说服力（约 3.5–5.5 人日）

- [ ] **P1-1 洞察引擎**（2–3d）
  - 规则：近 7/14/30 天频率、时段分布、分类集中度、环比变化。
  - API：`GET /insights`（观察 + 依据记录 + 时间范围）；`POST /insights/:id/feedback`。
  - 前端：洞察页/总览区块，卡片可展开依据，反馈三态（有帮助/不准确/不再显示）。
  - 验收：每条观察都能列出依据流水 id 与时间范围；反馈后不再出现。

- [ ] **P1-2 周度回顾**（0.5–1d）
  - 每周一汇总上周支出/收入/分类变化/预算执行，生成一段可读摘要（模板或 LLM）。
  - 验收：数字与账单页一致；可回看历史周。

- [x] **P1-3 交易编辑/删除 UI + 手动记账**（已完成 2026-11-12）
  - 账单页新增「＋ 新增账单」弹窗；行展开后可编辑/删除（二次确认）。
  - 筛选项：开始/结束日期、最低/最高金额（服务端过滤），分类/关键词仍即时过滤。
  - 复用并扩展 `POST/GET/PATCH/DELETE /chat/transactions`；金额统一走「分」。
  - 验收：接口 CRUD + 日期/金额筛选用例通过；真实 API 实测新增→筛选→修改→删除全链路。

## 三、需要先定的产品决策

1. **信息架构**：展示页是「Companion / 洞察 / 记忆 / 人格」四个一级入口；我们现在是「助手 / 总览 / 预算 / 账单 / 我的」。
   建议保持 5 Tab，把「洞察」并入总览、「记忆 + 人格」并入我的；若要 1:1 还原展示页则改为 7 个入口（改动较大）。
2. **主动消息渠道**：v1 只做站内（写入会话 + 红点），还是直接接 Web Push？
3. **人格是否影响决策**：仅改语气（成本低），还是影响「是否开口」（需要决策层，P0-4 依赖）。

## 四、建议迭代顺序

1. Sprint A（P0-1 + P0-2）：对话上下文 + 人格设置 → 可演示「同一个人格差异」。
2. Sprint B（P0-3 + P1-1）：记忆 + 洞察 → 可演示「依据 + 可纠正」。
3. Sprint C（P0-4 + P1-2/3）：主动关怀 + 周报 + 交易管理 → 可演示「到点主动出现」。

> 展示页里「主动消息/persona/记忆」目前均为前端模拟；本清单完成后，这些能力才有真实后端支撑。
